# Services

## Guard against concurrent PermissionSyncService::sync() runs
PermissionSyncService::sync() is called from the AppServiceProvider boot guard (every web+console boot), the PermissionSeeder, and the permissions:sync command. Eloquent syncPermissions() does DELETE+INSERT without a lock, so two overlapping syncs race and throw "Duplicate entry ... role_has_permissions.PRIMARY" (SQLSTATE 1062). sync() is wrapped in Cache::lock('permissions:sync', 60) that skips when already held — keep any sync-within (role=permission grants) inside that lock body. Boot guard already swallows+reports errors.

## Booking number sequencing lives in BookingSplitService and must skip split suffixes
All booking number generators (nextBookingSeq, nextBookingNo, nextReportingNo, nextSplitBookingNo) live in BookingSplitService; BookingController delegates. nextBookingSeq() MUST strip trailing "-NN" groups BEFORE pulling digits — a naive preg_replace('/\D/') turns AMSTSTDST000001-01 into 100001 and pushes every later booking up by 100000. Split children get number {parent}-NN and parent_booking_id, never a fresh sequence. Locked by tests/a_split_child_does_not_disturb_the_booking_number_sequence and test_split_numbering_increments_for_each_child.

## BL Detail PDF uses FPDI+FPDF, not TCPDF
The BL template (resources/pdf/bl-detail-template.pdf) is Illustrator vector artwork with all glyphs outlined — no text layer, no AcroForm fields — so values are stamped on top at absolute coordinates with setasign/fpdi. Use setasign/fpdf, NOT tecnickcom/tcpdf: TCPDF 7 ships no font files and its metrics (helvetica.json) live in tc-lib-pdf-font/target/fonts, which is not distributed — it must be generated by util/build_fonts.php, which downloads from the internet. FPDF's core fonts are built in. TCPDF-only methods used to exist here: SetPrintHeader, SetPrintFooter, SetCompression, setCellPadding do not exist on FPDF.

## BL Detail PDF field coordinates are read off the artwork, and text is clamped
The ZONES coordinates are PDF points on A4 (595.3x841.9), derived from the template's own ruled lines (extract with PyMuPDF page.get_drawings()); re-derive them if the artwork changes. Captions are printed INSIDE several boxes (Bill of Lading No., Notify party), so values start below them. writeBox() pre-wraps and caps line count to the box height, appending '...' — without that clamp an overflowing Description of Goods prints across the row below on a legal document. SetMargins(0,0,0) also zeroes the cell margin so text lands flush on the coordinates.

## BL Detail PDF: measure caption-to-value gaps, don't eyeball them
Several boxes print their caption INSIDE the cell (Shipper, Consignee, Notify party, Bill of Lading No.), so the value must start below the caption, not just below the cell's top rule — at y=124 the Shipper value sat 1.2pt under the caption and read as touching. Every captioned field now clears its caption by ~6.0-7.0pt; verify by rendering at 300dpi and comparing the caption's last ink row against the value's first ink row, not by eyeballing a screenshot or trusting the ZONES y value (y is text-box top, ink starts ~1.8pt lower). The particulars columns are different: their captions sit in the header row ABOVE the rule at y 375.6, so values clear the rule instead.

## Container Info syncs one row per equipment line, null-only
BL Info > Container Info lives in `booking_bl_container_infos` (created 2026-10-10), one row per booking_info_equipments line keyed by a unique `equipment_id`; it is NOT the legacy `bl_container_infos` table, which stays untouched holding longText blobs for the unbuilt Ref NO's / Stamps screens. Row endpoints in BlInfoController must keep their JSON 422 via ContainerInfoRequest::failedValidation (non-api AJAX otherwise 302s).
